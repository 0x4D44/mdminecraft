## Detailed Task Breakdown

### Phase 1: wgpu Renderer Integration (2-3 days)

#### Task 1.1: Basic wgpu Setup
**File**: `crates/render/src/gpu/mod.rs`
- Create wgpu instance, device, queue
- Setup swap chain for windowed mode
- Create render pipeline for chunk meshes
- Implement vertex/index buffer management
- **Tests**: Headless device creation, buffer allocation

#### Task 1.2: Shader Implementation
**Files**: `crates/render/shaders/chunk.wgsl`
- Vertex shader: position, normal, block_id, light level
- Fragment shader: texture atlas sampling, lighting calculation
- Uniform buffers for view/projection matrices
- **Tests**: Shader compilation validation

#### Task 1.3: Texture Atlas System
**File**: `crates/render/src/texture_atlas.rs`
- Load block textures from asset pack
- Build texture atlas with deterministic packing
- Generate atlas hash for snapshot stability
- Implement UV coordinate mapping
- **Tests**: Atlas generation determinism, UV mapping correctness

#### Task 1.4: Render Loop Integration
**File**: `crates/render/src/renderer.rs`
- Integrate with existing ChunkMeshCache
- Implement frustum culling
- Upload mesh data to GPU buffers
- Render opaque pass (other passes deferred)
- **Tests**: Frustum culling accuracy, draw call batching

#### Task 1.5: Headless Rendering
**File**: `crates/render/src/headless.rs`
- Implement off-screen render target
- Deterministic camera positioning
- Image capture and hashing
- **Tests**: Snapshot determinism across runs

### Phase 2: Camera & Player Physics (2 days)

#### Task 2.1: Camera Controller
**File**: `crates/client/src/camera.rs`
- Free-look camera with yaw/pitch
- View matrix generation
- Configurable FOV and near/far planes
- Smooth interpolation between ticks
- **Tests**: View matrix correctness, gimbal lock prevention

#### Task 2.2: Input System
**File**: `crates/client/src/input.rs`
- Mouse look with sensitivity config
- WASD movement input capture
- Jump/crouch/sprint modifiers
- Generate deterministic InputEvent stream
- **Tests**: Input event serialization, rebinding

#### Task 2.3: Player Physics
**File**: `crates/physics/src/character.rs`
- Capsule collider implementation
- Semi-implicit Euler integration
- Gravity and friction
- Step-height support (0.6 blocks)
- **Tests**: No tunneling at 6 m/s, stable standing

#### Task 2.4: Collision Detection
**File**: `crates/physics/src/collision.rs`
- AABB vs voxel grid collision
- Swept capsule tests
- Response with sliding
- **Tests**: Corner cases, edge stability

#### Task 2.5: Movement Integration
**File**: `crates/client/src/player.rs`
- Connect input → physics → transform
- Client-side prediction
- Interpolation between ticks
- **Tests**: Prediction accuracy, no jitter

### Phase 3: Interactive Gameplay (1-2 days)

## Risk Mitigation

### Risk: wgpu platform compatibility
**Mitigation**: Start with DX12/Vulkan only, add Metal later if needed

### Risk: Physics instability
**Mitigation**: Use proven algorithms, extensive unit tests, fixed timestep

### Risk: Performance regression
**Mitigation**: Add benchmarks early, track metrics per commit

### Risk: Non-deterministic rendering
**Mitigation**: Lock texture atlas, fixed camera paths, no temporal effects
